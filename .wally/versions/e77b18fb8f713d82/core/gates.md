# SOP 2.0 质量门禁

## 规则与证据

Core 定义质量要求，项目配置绑定语言版本、命令、阈值及扩展规则；项目已有更严格的约束继续生效。不能以 Profile 或风险等级静默降低门禁，冲突需说明并解决。
结果记录为通过、失败、未验证或不适用。不适用必须有依据；缺工具、空结果、全跳过及不可访问均不等于通过。
证据包含执行命令、代码版本、输入/环境、用例或报告标识、关键输出和结论。只引用本次已读、已执行的证据；本地临时报告需将必要摘要落入阶段产物。

## Clarify / Plan

- 明确可验证目标、范围、依赖和未决问题；业务决策未解决不得凭猜测实现。
- Plan 先设计 UT/IT：正向、逆向、边界、异常恢复；按实际影响检查调用链、fallback、retry、多终态出口、副作用挂点、兼容性与回滚。
- 写操作验证幂等，外部依赖验证异常。显式声明 UT Mock 边界；场景测试仅隔离外部依赖。涉及失败副作用时同时覆盖终态触发一次、中间失败但后续成功不触发，逐个核对终态出口。
- 方案以实际关键代码、既有测试、相关架构/接口及上下游契约为依据；未定位责任边界先补读，不仅凭对话推测。
- 涉及 JSON 或中文数据时，UT 和适用的 IT 均设计 Unicode 用例。
- Bug/性能任务定义问题判据、最低可复现层级、修复前后输入、等价条件及指标；环境基线无法重跑时明确可用历史证据及限制。

## Implement

- 先写能暴露问题的测试，再实现；Red 必须是预期断言失败，环境/语法失败不算。Green 使用同组断言；重构后保持通过，无需重构时说明。
- 覆盖率使用新增/修改生产代码的增量行与分支口径，按项目配置的代码分类阈值核验。无可执行分支可标 N/A；无法生成报告时不得编造或用全量覆盖率替代，由用户明确决定未验证边界。
- 自动生成代码、纯声明和其他不适用项必须提供依据；文档类任务不伪造 Red/Green。不适用范围之外的门禁仍需执行。
- 完成 Docs 影响评估并更新权威文档，避免双轨；按项目规则路径与实际语言/解释器版本增量 CR，核验安全、并发、幂等、异常和兼容性。高严重度问题未解决不得进入交付。

## Deploy / IT / 缺陷闭环

- 部署有范围、版本、生效证据与可执行回滚；测试具备数据隔离、鉴权及清理策略。
- 按 Plan 逐项核验实际测试结果，除断言失败外也核验执行/环境错误。跳过原因、未覆盖范围和残余风险明示，不仅看退出码。
- 已配置环境验证的 Bug/性能任务：A 优先真跑未修复基线；无法真跑时仅采用已留存且可比的历史证据并说明原因。B 必须在等价可控条件下执行，性能需多轮统计。A 无有效证据或 B 不通过不得 Commit。
- Deploy/IT 未配置时自动 SKIPPED，不要求环境级 A/B；保留代码层 Red/Green 等适用门禁，并明确环境级 A/B 未完成，禁止声称端到端修复已验证。已配置后的失败不能用此例外放行。

## Review / Commit

复核最终 diff、实现与 Plan 差异、各适用门禁、文档、缺陷证据及时间记录。按项目提交规范和授权准备提交；有 Token collector 时主动执行对应报告入口并读取结果，失败不能拿旧报告充数。缺失/不支持/采集不完整不得解释为零消耗，禁止手填报告。
没有安装 collector 时如实记录“未启用”，不为生成零报告安装额外客户端。Git、外部系统和资源释放分别按实际授权执行。

## 时间记录硬门禁

Review 前检查本任务 overview：新任务恰有 01–06 六行；已完成步骤的开始/结束、耗时、对话轮次齐全，时间精确到秒、顺序合理，Progress 与实际阶段产物对应。
只有本任务对话可定位的真实起止才可补齐并注明“补齐：对话证据 …”；无证据保持空白，退回缺步重做并当场记时。空白、“漏记”“无对话证据”“本次补录”或 Review 时集中伪造前序产物均不通过，不得有条件放行。
合法承接/跳过须记录理由和完整时间行：开始=结束，耗时 0s、对话轮次 0；未配置而自动跳过的 Deploy/IT 使用任务创建时的真实跳过决定时间（开始=结束）、0s、0 轮，备注未执行，不把该时间当作实际执行顺序。Review 进行时自己的结束时间可暂空，完成审计与给出通过结论前必须补齐；无需为记时新增开始/结束确认。

## Token 对话汇总

采集明细保留逐请求语义；写入 overview 的提交报告按一轮用户对话一行：Codex 同线程/根轮次调用求和，CodeBuddy 同会话连续相同 Prompt 请求求和，Cursor 的整轮累计已取最大值去重，不能再按 step 求和。原始 token.json 不提交；报告仍明确采集状态与快照边界。

## Docs 验收

按绑定版本 `knowledge.md` 执行。记录源码到文档的影响关系与实际验证；最终 Review 同时覆盖 Deploy/IT 期间的变更。过期页未解决或更新未验证时，Docs 不得通过。
