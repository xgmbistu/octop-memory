# SOP 2.0 交互与风险

质量门禁与用户确认分开。用户已授权的任务内连续执行可逆的本地工作，并在阶段完成时汇报结论、证据、耗时和下一步；不为每步重复请求开始/结束确认。

## 需要暂停的位置

- 缺少会改变实现的业务输入、重大设计取舍或相互冲突的项目规则。
- 操作超出既有授权，或当前工具/环境要求额外批准。部署共享/生产环境、删除资源、外部系统写入、Commit/Push 等按具体作用范围判断；已有明确授权持续有效，不能把“开始 SOP”扩大解释为任意外部写操作授权。
- 用户要求停在方案、开发或提交准备时，在该边界停止后续动作。

把待决事项与可供评审的结果一起提出；等待期间继续不依赖该回答的工作。已经明确的信息、授权和执行位置写入 overview，不重复询问。用户沉默不算授权。

## 风险与记录深度

- 低：局部、可逆、不改外部契约或数据结构。用简短事实与证据链接完成同一模板。
- 中：跨模块、公开接口或非平凡状态逻辑。补齐影响链路、异常路径、兼容及回滚说明。
- 高：跨组件、数据迁移、安全、计费、并发一致性或高影响环境。展开失败恢复、基线、验证边界及发布/回滚条件。

Agent 根据实际影响推荐并记录风险及依据；有实质争议或需要新决策时让用户决定，不固定增加一次启动确认。发现范围扩大立即升级风险、补充 Plan 与验证。不得仅按代码行数划分风险，不维护三套模板；低风险不豁免适用门禁。

## 执行位置

默认在用户当前授权的执行位置继续。用户选择托管后记录委托决策，读取项目扩展的委托指引并完成交接后停止本地后续阶段。没有选择云端或外部执行时不主动发起委托。已有选择不再强制二选一。
