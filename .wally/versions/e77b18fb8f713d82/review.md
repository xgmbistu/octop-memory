# 代码 Review 指南

> AI 与人类 Reviewer 共同遵守的检查清单。
> **增量审查主场**在任务 `03-implement.md` 的增量 CR：先读取本任务项目配置指向的相关规则文件，再按本文通用清单审查。冲突以项目 rules 为准。禁止按「最新语法」审查。
> Step 6 Review + Commit 只做增量复核，不把本清单再抄一遍。
> 进入通用清单之前，先过「SOP 流程合规检查」。时间记录有空白、漏记或后补，Review 不通过，不得继续代码审查。

---

## SOP 流程合规检查（P0，不过则 Review 不通过）

先按当前分支定位本任务 overview，读取它绑定的 Core `gates.md` 中“时间记录硬门禁”和项目配置快照。无版本历史任务按 compat/v1 的旧审查规则执行。
时间行、Progress 和实际阶段产物必须一致。前序步骤有空白、漏记、无证据或 Review 时集中后补，均不通过；只能按真实对话证据补齐，找不到证据则退回缺步重做并当场记时，不能用“未编造”当作审计通过。
新任务固定为 01–06。合法承接/跳过须保留依据与完整时间行；Deploy/IT 仅在 execution.json 未配置 command/guide 时自动跳过；已配置后不能因低风险或执行失败而跳过。自动跳过行记录创建任务时的决定时间，不冒充执行起止。Review 自己进行中可暂缺结束时间，给出通过结论前须齐全。
Meta 核验分支、SOP 版本/规则路径、项目配置快照、任务类型、状态、风险依据与授权边界；已完成阶段必须有实质产物。任务规则缺失不能回退最新版。
本关失败不得给出“通过”或“有条件通过”，修复后再进入以下清单。确认节奏按该任务交互规则执行，不恢复机械五段式。

## 分类与优先级

| 严重度 | 说明 | 处理 |
|--------|------|------|
| 🔴 高（阻塞） | 安全漏洞、数据丢失风险、协议破坏、性能回归 | 必须修复才能合入 |
| 🟡 中 | 可测性差、边界漏判、错误处理缺失、命名混乱 | 需修复或明确记录 |
| 🟢 低 | 风格建议、重构空间、文档补全 | 可选 |

---

## 必查项（高严重度）

### 安全
- [ ] 所有 SQL 使用参数化查询，无字符串拼接
- [ ] 无硬编码密钥、Token、密码
- [ ] 输入校验覆盖所有外部来源（HTTP 参数、消息、文件）
- [ ] 输出按场景转义（HTML / SQL / Shell）
- [ ] 加密使用标准库

### 正确性
- [ ] 边界条件覆盖（空、单元素、超长、负数、越界）
- [ ] 并发读写共享资源有保护
- [ ] 事务边界清晰，失败回滚正确
- [ ] 对外接口遵循幂等 / 重试 / 超时约定
- [ ] **失败触发副作用的逻辑**（熔断 / 告警 / 扣费 / 状态写入）已绑定到**全链路终态出口**，不存在中间失败误触发
- [ ] 已核对 fallback / retry / router 重投 / 老链路兜底 / 多终态出口，确认副作用挂点不早、不漏

### 可观测性
- [ ] 关键路径有日志，包含 trace_id / request_id
- [ ] 错误路径日志包含足够上下文
- [ ] 监控指标 / 告警已配置

## 常规检查项（中严重度）

### 可测性
- [ ] 存在对应的 UT，且 `03-implement.md` 已记录 Red → Green → Refactor
- [ ] 增量行 / 分支覆盖率达到本次代码类型门禁（不是项目全量覆盖率）
- [ ] 公共接口有契约（输入/输出/异常）
- [ ] 无隐藏的全局状态

### 可维护性
- [ ] 命名清晰，避免缩写歧义
- [ ] 函数短、职责单一
- [ ] 公共代码抽取到合理层级
- [ ] 无重复代码（规则：相同逻辑出现 3 次以上必须抽象）

### 兼容性
- [ ] 协议变更向后兼容（新增字段不破坏旧客户端）
- [ ] DB schema 变更支持回滚
- [ ] 依赖版本与项目约束一致

---

## 建议项（低严重度）

- [ ] 注释说明「为什么」而非「是什么」
- [ ] 文档同步更新（`.wally/docs/apis/`、`.wally/docs/sqls/`、`.wally/docs/overview/system-architecture.md`、`.wally/docs/devops/`、`.wally/docs/unittest/` 等按改动涉及的目录补）
- [ ] 测试数据逼真
